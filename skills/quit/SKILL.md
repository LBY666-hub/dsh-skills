# 退出会话总结

当用户发出退出会话的意图（如发送 `/quit`，或说"结束 / 退出 / 再见 / 我走了"）时，**不要继续新任务**，而是按下面的固定格式给出一份条例清晰、一眼能看清的总结，然后作简洁收尾。

## 输出格式（分条 + 加粗标签）
1. **做了什么** —— 一句概括本次会话/本次完成的主要内容。
2. **产物/位置** —— 产生的文件、仓库、网址、路径（给出具体位置，别用模糊说法）。
3. **当前状态** —— 做完 / 进行中 / 待办。
4. **可继续的事项** —— 1~3 条下一步可选动作。

## 要求
- 只总结"有产物 / 有实际改动 / 有结论"的内容，不闲聊式堆叠。
- 若本次会话没有实质产物，给一句简短说明（如"本次会话未产生文件/改动"）。
- 结尾用一句友好的道别即可。
- **不要写入 token、密钥、密码等敏感信息。**

## 示例
> **做了什么**：完成刷题App从题库构建到发布 GitHub Pages 全流程，并沉淀为可复用 Skill。
> **产物/位置**：本地 `刷题App\`；GitHub `LBY666-hub/marketing-brush-app`（页面 https://LBY666-hub.github.io/marketing-brush-app/）；Skill `shuati-github-build`。
> **当前状态**：已完成、已上线。
> **可继续事项**：① 验证 Skill 可用性；② 给 App 加功能（收藏/进度/导出）；③ 优化手机安装体验。
